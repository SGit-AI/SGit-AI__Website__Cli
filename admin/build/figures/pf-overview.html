Is there any overhead? Yes: a fixed cost per command. The rest is what you choose to fetch.

Four answers, each measured, from the smallest unit up. A command costs a fraction of a second before any network; after that the cost is the number of requests, and sgit's clone options decide how many of them a job makes. Local numbers are local; the hosted ones are from a cloud sandbox behind a proxy.

1. One command

≈ 0.4 s

fixed, before the network: 0.22 s to start, 0.18 s for the 600,000-round key derivation, once per process. Encryption itself is cheap: 100 MB in 0.4 s.

this sandbox, 21 Oct, sgit-ai 0.23.0

2. A CI job

0.59 → 0.77 s

a one-folder clone as the vault grows from 100 to 2,000 files; a full clone goes 0.95 → 5.55 s. Ten one-folder clones at once: 1.9 s; ten full: 21.1 s.

sgit in GitHub Actions, side by side; local server

3. A big vault

13 s, 3 MB

one folder at one commit of a 35,000-object, 527 MB vault, hosted; a full clone is 3½ minutes. From local disk, 0.8 s. A pull with nothing new: 2.5 s.

One vault, ten agents; hosted server, cloud sandbox

4. Many writers

205 / s

a hundred writers, a thousand entries into an append lane in 4.9 s, none lost, in memory. A hive: 603 operations in 27 runs, median commit 0.83 s, push 1.0 s.

Agent workflows on ephemeral vaults; the ruv.sgit ledger
