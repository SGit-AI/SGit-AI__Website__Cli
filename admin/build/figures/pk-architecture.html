A pack per push: what the host holds, and what each operation costs

Every push uploads one zip of the commit's new objects; a clone takes the newest snapshot and the packs since it; compaction folds packs into a new snapshot and moves them to the archive, deleting nothing. The ref, the branch index and the cache stay as they are. Dashed boxes are proposed, not built; the routes on the right exist on the server today.

1. Push

Build one pack per commit, upload it, move the ref by compare-and-swap.

2 to 3 requests, any size

2. Pull

List commits/, fetch the packs not yet absorbed, verify every member by id.

1 listing + the missing packs

3. Clone

Newest snapshot, then everything in commits/. No commit walk.

2 listings + 1 snapshot + a few packs

4. Compact

Write a snapshot, read its directory back, then move the packs it absorbed to archive/.

any writer, by count or size
