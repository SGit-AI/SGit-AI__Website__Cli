Pack mode: five decisions before the CLI team builds it

Read from the spec, the article draft and the brief to the SG/Send team, written within an hour of each other on 20 and 21 October. The design is sound and needs no server change; these are the five places where a choice is still open or two documents disagree. Each card says what is at stake and what I would recommend.

decide first

1. Which design: one zip appended, or a pack per push?

The brief of 20 Oct, 23:17 asks SG/Send for an append route, to grow one, two or three zips in place. The spec of 21 Oct, 00:05 chooses a pack per push, which needs no server change, and moves the append route to "later".

Recommend: the pack per push, as the spec says.
tell a team

2. What the SG/Send team should do with the brief

It says the CLI "is going to try a storage mode" of one to three zip files, and lists six server tests to write. None of its three asks blocks the spec's first version; the pack names already carry the size.

Recommend: park asks 1 and 2, keep 3 as nice to have, say so to the team.
cost

3. Scoped clones get bigger in version 1

A clone takes the snapshot whole. The agents' daily --path X --depth 1 clone of the comms vault is 13 s and 3 MB today; in a pack vault it would be the 430 MB snapshot. The spec's four runs do not measure it.

Recommend: add it as run 5; keep agents on loose vaults until Range reads land.
cost

4. Orphan packs are fetched for ever

A push whose ref move fails leaves its pack in commits/. Compaction ignores unreachable packs, and a clone fetches everything in commits/, so an abandoned pack is downloaded by every clone until a prune exists.

Recommend: compaction moves unreachable packs older than a day to archive/.
say it

5. What the listing tells the host

Pack names show each push's commit id, its total size and the writer's clock in milliseconds. Today the host sees object sizes and request timing; the per-push grouping and the writer's own clock are new, and small.

Recommend: state it on the security page when the mode ships.
sound

What I would not change

  • No server change, every route already live
  • Deterministic packs, verified by id on arrival
  • Extraction first, so every read path is untouched
  • The format gate, so old readers refuse by name
  • A separate trial vault, nothing deleted
