Indexes the writer pays for, read one member at a time

The design principles Dinis Cruz set out, built as plain JSON in one zip and measured on the 76,000-file vault (58,062 folders, 20,003 commits). The writer computes every cross-reference once; a reader opens the zip without its central directory and loads only the members a question needs. Dashed: proposals, not sgit code.

The writer pays

once per push, by the agent that changed the files
3.5 s

to build every index of the vault from scratch

one commit of 5 files
  • 38 members rewritten, 57 KB, in 10 ms
  • 27 of them are the folders on the five files' paths, the same path a Merkle tree rewrites
  • the rest: the shards those files and the commit fall in

One zip, plain JSON members

23.4 MB, 58,598 members, each deflated
offsets.jsonfirst member: where every other one starts
folders/<id>.json58,062 · entries + totals of the subtree · 226 B
xref/blob-paths/<xx>.json256 shards · blob → paths
xref/file-commits/<xx>.json256 shards · file → commits
xref/commits-by-gen/<n>.jsonby generation · parents, gen, time

Every link is stored in both directions, so from any id a reader finds everything that points to it.
