Release history

The site's version is in admin/build/version.txt and goes up on every push to dev; the badge at the top of every page reads it. The command reference carries its own version, the sgit-ai release it was generated from.

VersionDateCommand referenceWhat changed, and why
v0.2.212026-10-28sgit-ai v0.26.8Two more builds reviewed under Builds: 0.26.7 (a signer's own SSH or OpenPGP signature on a commit or tag can be verified; nothing makes one yet, commit -S is parked until the web UI confirms the signing-bytes rule, W-1) and 0.26.8 (history blame, sgit grep, log -S and -G, rename detection, a patch that is git diff's). Each package matched to its tag; 5,235 and 5,436 tests; against git, blame 25/25, renames 90/90, grep 120/120, log -S/-G 40/40 (against git --no-renames); signed commits read by 0.26.0, 0.26.3 and 0.26.6; vaults of 0.20.0, 0.22.0, 0.24.0 and 0.26.0 (normal and pack) open and round-trip. Found: BR-5 (low: sgit grep with a 1,001-character pattern exits 1, not 2), BR-6 and BR-7 (differences from Git to document: the pattern syntax, -S and renames); BR-1 still open. The command reference regenerated from 0.26.8: three commands added (grep, file grep, history blame), 177 in all.
v0.2.202026-10-28sgit-ai v0.26.0A new section, Builds: every sgit-ai build on PyPI since 0.26.0, with release notes and a review by cli.build that the CLI team's agent reads directly. Six builds, 0.26.1.dev0 to 0.26.6: pack index verify 120 times faster, a new pack vault's gate fixed (R3-2), Git-parity phase 0 (commit refused during a merge, deep forks, nested vaults), 64 KB messages, opt-in line-level merge, commit <paths> and hunk commits. Each package matched to its tag; 4 suites, 7 builds × 19 end-to-end checks, 18,000 merges against git merge-file, cross-version with 0.26.0 and 0.26.3. Every claim held. Found: a push of more than 100 commits leaves a gap in the host's history, in every build since 0.26.0 (BR-1, high); line merge can be clean where Git conflicts on repeated lines (BR-2); a plain pip install now takes dev builds (BR-4, a decision). The Git-parity roadmap and its eight designs imported as research; sgit and Git shows Git's lead closing, with GitHub's features moved to a future server. The importer now rewrites relative links between imported documents.
v0.2.192026-10-28sgit-ai v0.26.0The site leads with what only sgit does. A new page, sgit and Git, first under Get started: twelve things Git has no equivalent for, each with its command and Git's nearest answer; fifteen both have, with the difference; sixteen where Git is ahead, with how sgit would build each on the client and its size; six ruled out by zero knowledge, with substitutes; and the qualifiers (TM-R01, TM-R42, TM-R12, what the host sees). Built from the CLI team's review of the newsroom's article, published as written, with the rewind guard, the secret guard and sgit write re-run against PyPI 0.26.0. A new research topic, sgit and Git. The home page's title and lead changed from "git for encrypted vaults" to what only sgit does, with the figure. Corrected: the limitations page (partial commits exist; commits are signed and verified; what a signature proves; the stale reference line), the Git users' guide (write, clone options, checkout), and What is sgit. The 0.26.0 notes say R3-2 is fixed on the CLI's dev for the next release.
v0.2.182026-10-27sgit-ai v0.26.0sgit-ai 0.26.0 reached PyPI on 27 October, eighteen hours after 0.25.0, and this release documents it. Release notes: index packs beside every data pack, a selective working copy (clone --no-checkout, sgit checkout), the pack store, one folder of a pack vault by byte ranges; on 76,000 files a full clone 117 s → 61 s, a pull 81 s → 6.6 s, history log 3.2 s → 0.45 s; the compatibility rules and the known limits. Pack indexes, shipped tells how it went from the newsroom's first morning to the release and links every document in order. Nine research documents added: six from the CLI team and cli.build's three reviews, with their scripts. The command reference is regenerated from 0.26.0 (174 commands, 9 added). The dev pack, the three articles before it and the scale topic say it shipped.
v0.2.172026-10-26sgit-ai v0.25.0A second dev pack, Pack indexes for sgit, the implementation spec for the CLI team: index packs beside data packs under bare/packs/indexes/ (no gate: 0.24.0 to 0.25.0 never list it), an encrypted signed header with opaque member names, the JSON schemas of every member, path-ordered data packs with offsets for ranged scoped reads, the writer's and the reader's work command by command, the threat model, four phases with acceptance tests and benchmark targets. Checked against SGit-AI__CLI at c0694753.
v0.2.162026-10-26sgit-ai v0.25.0Index deltas in every commit pack, measured at Dinis Cruz's question: 1,000 commits of five files on the 76,000-file vault; folder files plus a change list cost 3.1 KB a commit (3.0 MB for all 1,000) against 47.7 KB when whole cross-reference shards travel, and a reader applies 1,000 change lists in 49 ms. A section in Indexes the writer pays for, the numbers in the research record, the scripts in the repository.
v0.2.152026-10-26sgit-ai v0.25.0Indexes the writer pays for, by cli.build on Dinis Cruz's design principles: plain JSON cross-references built once by the writer, one file per folder, shards loaded on demand; measured on the 76,000-file vault (3.5 s to build, 38 members for a five-file commit, one member per question), on a synthetic link graph of a million pages (a fresh reader in 18 ms and 152 MB), and against MGraph-DB 1.18.0 and Memory-FS 0.41.0. Every number of the day's three articles kept in a research record, and the scripts and raw results in the repository under admin/research/graph-and-index-poc-2026-10-26/.
v0.2.142026-10-26sgit-ai v0.25.0A vault is already a graph, by cli.build at Dinis Cruz's question: a vault's files and history as 482,532 triples, eight questions asked in nine engines (Python, SQLite, networkx, Oxigraph, DuckDB, LadybugDB, Kùzu, rdflib, MGraph-DB), every answer checked; generation numbers answer the merge base and base..head in 0.1 ms against 17 ms to 5 s in the engines; triples ship encrypted at about 3 MB for the whole set or 203 bytes a commit; a graph engine as an optional local view, Oxigraph first. A dated update on the indexes article points to it.
v0.2.132026-10-26sgit-ai v0.25.0Indexes in the pack, reviewed and measured: an article by cli.build on Dinis Cruz's proposal and the CLI team's design, with the numbers on a 76,000-file vault (the head's index 2.4 MB deflated, 0.32 s into SQLite; one folder of a pack vault in one ranged read instead of 265 when blobs are in path order), a correction (0.25.0 re-downloads a pack with an unknown member rather than refusing it), and three changes proposed: an index pack beside each data pack, JSON on the wire with SQLite built locally, built databases only where building is the cost. The CLI team's two documents published as research, imported at c069475; the importer gains --only.
v0.2.122026-10-26sgit-ai v0.25.0sgit-ai 0.25.0 reached PyPI on 26 October and this release documents it. Release notes: on a vault of 76,000 files a one-file commit went from 29 minutes to under 5 seconds and a status from 71 seconds to about 4; what changed, the data-loss bug a review found in the scan cache before release and how it was closed, the two new cache files, and what is still slow. The command reference is regenerated from 0.25.0 (165 commands, unchanged), and the performance article links to the notes.
v0.2.112026-10-24sgit-ai v0.24.0A new section, Dev packs: designs to build from. The first is Sealed vault keys for sgit, from a design session of Dinis Cruz's with a Claude agent: four components (cli, fs, net, kms) under Process Behaviour Policies, a KMS protocol, mutual TLS with a session CA, and the measured evidence. Reviewed before publishing by cli.build: compatibility made a requirement at Dinis's instruction (a new document, 05: with nothing switched on sgit runs as 0.24.0 does, opt-in per clone, five rollout stages in production, rollback at each); the handover's one-week expiry no longer applied to what a clone keeps; trust by a pinned fingerprint first, since the KMS has no network; the threat model says when local defences bind a root agent; the platform's proxy port generalised.
v0.2.102026-10-24sgit-ai v0.24.0Sealed vault keys, from two sides: the requirements another agent working with Dinis Cruz on pki.sgit.ai wrote from a fortnight of moving vault keys (R1 to R10, seven acceptance tests), published as written, and a side-by-side review by cli.build: every claim checked against sgit 0.24.0 (14 commands take a key on argv; sgit names the encryption fingerprint where the register uses the signing one), what each document adds, the open questions answered, one list in four phases and fifteen acceptance tests. A vault key that never lands gains a dated update.
v0.2.92026-10-24sgit-ai v0.24.0Two proposals from Dinis Cruz's message, for implementing next: A vault key that never lands, native PKI in sgit so a vault key arrives sealed (pki.sgit.ai's QR handover), stays sealed on disk and is opened only in memory by an sgit agent, mapped against sgit 0.24.0's code (27 places read the key file; the clear key, the read key, the token and the signing key are all on disk in clear; sgit pki private keys use 2,048 PBKDF2 iterations); and A second factor without a server: why an authenticator app's code cannot protect a vault without a server, how a passkey's PRF or a security key's hmac-secret can, and a person as an agent's co-signer. Two figures, two diagrams; the keys topic gains both.
v0.2.82026-10-22sgit-ai v0.24.0Pack mode, released: sgit-ai 0.24.0 reached PyPI on 22 October and this release documents it. Release notes and a playbook for agents, both run against the PyPI build on dev the same evening; the command reference regenerated from 0.24.0 (165 commands: sgit pack and six subcommands, --packs on init and create); Four rounds to no blockers, the build agent's account of reviewing pack mode before release; measured numbers added to Is there any overhead? and A pack per push; the CLI team's eight new pack documents and this site's four verification reports under research, re-imported at 182cfc1; topic rows moved to shipped.
v0.2.72026-10-21sgit-ai v0.23.0HTTPS is enforced: Dinis Cruz ticked "Enforce HTTPS" in the repository's Pages settings, and http://cli.sgit.ai now answers 301 to https://, as sgit.ai and the newsroom do. The reality file moves it from "does not exist yet" to "exists".
v0.2.62026-10-21sgit-ai v0.23.0Is there any overhead?, an answer to a reader's question on LinkedIn about performance (the question quoted, its author not named): the fixed cost of a command, a CI job's clone as the vault grows, the big vault, the ruv.sgit hives' 603 operations, where sgit does less work than git and where git is faster, and what pack mode, compression and a commit-chain object add next; four drawn figures and a diagram for choosing the clone.
v0.2.52026-10-21sgit-ai v0.23.0A vault you can carry, from Dinis Cruz's message: the three kinds of object that let a vault mix mutable and immutable files, and a whole vault as one zip, sealed to a public key, with the round trip run and measured on a published vault. A pack per push gains the two modes side by side; the review is updated above its text with the five decisions taken and one of its notes corrected; research re-imported at 477d328.
v0.2.42026-10-21sgit-ai v0.23.0Diagrams at a readable size: each is shown at 75% of its drawn size and no taller than 720px, where they had stretched to the column (a pull flowchart's labels reached 40px on a wide screen); flowchart decisions are hexagons instead of diamonds and the layout is tighter, so the pull flow went from 1,364 to 810 drawn pixels tall; the import flow is top-down.
v0.2.32026-10-21sgit-ai v0.23.0Three fixes from reading the site on an iPad and an iPhone: every stylesheet and script is now asked for by a fingerprint of its contents, so a browser can no longer mix a cached v0.2.1 stylesheet with the new themes (which painted dark headings and grey text on Ember); the phone menu scrolls on its own instead of scrolling the page under it (the newsroom's fix); and the bar collapses behind Menu below 1,200px, where an iPad had wrapped it onto two rows.
v0.2.22026-10-21sgit-ai v0.23.0Five reading themes, the newsroom's: Newsprint, Night, Paper, Blueprint and Ember, chosen from a picker in the nav and remembered in the browser, with the system's dark setting as the default. Every colour in the stylesheet is now a token defined in all five, and the gate holds it so; figures and diagrams stay on light paper in every theme, as prints.
v0.2.12026-10-21sgit-ai v0.23.0The CLI team's pack-mode thread, made readable: A pack per push as an article with two drawn figures and six flow diagrams; a review of it with five decisions by the build agent; the spec and the brief to the SG/Send team under research; the zip article synced with its revised draft. Figures are now drawn the newsroom's way (an HTML page each, rendered to webp) and mermaid diagrams are rendered to SVG at authoring time. From here every release is a minor, at Dinis Cruz's instruction.
v0.2.02026-10-20sgit-ai v0.23.0Research and articles become two areas, from the second brief: 22 research documents as written under /research/ in seven topics, each topic a question with what is shipped, designed and absent; ten articles under /articles/ in the newsroom's format send.sgit.ai's guidance sets out, seven of them converted from the CLI team's drafts of 16 and 20 October, with lead figures; the gate holds articles to the format; the 21 v0.1 addresses send the reader on. A minor-version step because addresses moved.
v0.1.22026-10-20sgit-ai v0.23.0The reality file catches up: cli.sgit.ai was checked live after v0.1.1 deployed (DNS, Pages and the dev environment all work), so it moves from "does not exist yet" to "exists".
v0.1.12026-10-20sgit-ai v0.23.0The generator and the gate reach the repository: the Python .gitignore template's build/ rule had kept admin/build/ out of the v0.1.0 commit, so CI could not run validate.js and nothing deployed. .gitignore now re-includes admin/build/.
v0.1.02026-10-20sgit-ai v0.23.0The first version, built from the brief the same day: 27 pages moved from sgit.ai (site v0.7.87) so the CLI's technical documentation has one home, the command reference generated from sgit help all --format json (158 commands), and 23 research documents from the CLI repository (SGit-AI__CLI at 5597526) published as articles, with the generator, the gate and the deploy pipeline the sibling sites run.
