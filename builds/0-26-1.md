## What is new {#new}

- **`sgit pack index verify` is about 300 times faster.**
  - **What was slow:** for every `folder:` member it re-flattened the head, and every member read rebuilt the header's member table.
  - **On the newsroom's 79,465-file vault:** about 57 s a pack, and about 40 minutes in all, with no output.
  - **The CLI team's measurement:** 1,002 s → 3.5 s on 24,000 files and 9 packs.
- **One progress line per pack,** flushed as it goes, so a pipe or a file shows progress too: `3/9 commits 4b84cea48e03 — ok in 0.8s`.
- **`sgit pack index verify --last N`** checks only the N newest index packs, so "did my last push's index match?" costs under a second.
- **`sgit pack index stats`** explains its generation line: this clone's memo, which is 0 on a clone that only reads.
- **A new pack vault's gate is what its features need, 0.24.0,** not the creating build's version. `init --packs` and `pack import` used to write their own version, so a vault made by an agent on a dev build refused every agent on the release. This is [R3-2](../research/pack-indexes-review-round-3.md#r3-2), fixed. Existing vaults keep their gate; `sgit vault format --min-client` lowers it.
- **`sgit update --stable` and `--pre`** choose between the newest release and the newest build.
