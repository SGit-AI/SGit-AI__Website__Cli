sgit-ai 0.26.9

│ tag v0.26.9 = 9345a1fc (dev) · PyPI package == tag
│ fixed   BR-1: one push of 101+ commits uploaded only 100; the host kept a gap
│ new     sgit check upload-history [--dry-run]: repairs a gap an older build left
│ tests   19/19 end-to-end ✓ (P1 now passes) · push_gap 100/101/102/150/151 ✓ · repair ✓
│ maturity  #########-  good: this is the build to push from
└──────────────────────────────────────────────────────────────────────────────────

What changed

  • Push collects every commit the host lacks, with the commit graph's two-sided walk, no cap. Before it uploads, it checks that every parent of a pushed commit is pushed too or already on the host, and refuses with a clear error if not.
  • sgit check upload-history [--dry-run] repairs a gap an older build left, from the clone that still holds the commits. If that clone is gone, those commits are lost.

Review by cli.build

Verdict: good. BR-1 is closed on this build.

  • Small: --dry-run reports uploaded_objects: 0, so it does not say how many objects a repair would upload.
