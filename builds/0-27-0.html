The CLI team's rule for 0.27.0 was: nothing high or medium open, the checks for every claim since 0.26.0 hold on the candidate, and the cross-version checks pass. All three hold on 0.26.13.dev0.

After the release: sgit-ai 0.27.0 is on PyPI

Checked on the package PyPI serves, after it was published (28 October 2026, 21:53 UTC):

a push of 102 and 152 commits, then a fresh clone's fsckok (BR-1 stays fixed)

So the sign-off applies to 0.27.0 as published. The tests in the table below were run on the candidate; the code is byte-identical.

Condition 1, the yank, now matters less. 0.26.3 to 0.26.11 are still live, but 0.27.0 is the highest version, so a plain pip install sgit-ai, pip install -U sgit-ai and sgit update all reach it. A yank would only stop someone installing a dev build by accident with a loose pin. Condition 2, the web UI test with a signed vault, is still open.

Conditions that are not code

  1. Yank 0.26.3 to 0.26.11 on PyPI (optional now, see above). Only a PyPI owner can. None was yanked when I checked.
  2. Have the web UI team open one vault with signed commits and tags. The CLI team says the web UI never verifies commit signatures and ignores members it does not know; signing shipped on that. I could not test the web UI. Make the vault with scripts/xsign.py or signing_paths.py in the research folder.

Not tested

ssh-keygen as signer or verifier (not installed on the test machine; the in-process path was used), passphrase-protected keys, certificates, FIDO keys, check verify --require-user-signature and its exemption of the first commit, commit -p interactively, sgit update on the candidate, the web UI, and a real host (everything ran on the in-memory host, except the PyPI checks). Scripts and results: admin/research/builds-0-26-7-0-26-8-2026-10-28/.

Residual, accepted

  • BR-6, BR-7: differences from Git, documented. sgit grep reads git grep -E patterns; log -S/-G do not follow renames.
  • UP-1: a user on 0.26.3 to 0.26.11 cannot reach the dev channel with sgit update. Once 0.27.0 is published, their plain sgit update installs it.
  • R3-1, the other direction: a 0.25.0 client that compacts a vault this build wrote archives its own rebuild; pack index build --all refreshes the index. I could not make it fail.
  • Orphans: a failed signing leaves a blob and a tree, unreferenced.
