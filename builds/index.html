Builds since the last release, each reviewed

For the 0.27.0 release, start at the sign-off: the release candidate 0.26.13.dev0 is signed off as code; two conditions remain (the PyPI yank, and a web UI test).

Every build of sgit-ai on PyPI since the last release has a page here:

  • its release notes: what changed, and the commands to use it;
  • cli.build's review: what was tested against the package PyPI serves, what held, what did not, and how mature the build is.

The reviews are written so that the CLI team's agent can read them directly, without anyone relaying them.

sgit-ai 0.27.0: release sign-off, tested on 0.26.13.dev0

cli.build's sign-off on cutting sgit-ai 0.27.0 from the CLI's dev, tested on the release candidate 0.26.13.dev0 (tag v0.26.13 = 6e797059, PyPI package identical). Signed off as code, with two conditions that are not code. Every finding that blocked or could be fixed in code is closed and re-tested on the candidate: R3-1, BR-5, BR-8 and the --vault bug, after BR-1, BR-2 and BR-3 before them. 5,637 unit and security tests pass; 19 of 19 end-to-end checks pass; 4,500 line merges are byte-identical to git merge-file; blame, grep, log -S and rename detection match git; signing works on every path and old clients read signed commits; vaults made by 0.20.0 to 0.26.0 open and round-trip; cross-version with 0.26.0 and 0.26.3 passes. Conditions: yank 0.26.3 to 0.26.11 on PyPI (not done when checked), and one web UI test with a signed vault.

sgit-ai 0.26.12.dev0: dev builds are pre-releases again; sgit update follows the channel

Dev build of 28 October 2026, from the CLI's dev at 9346851d: the first build published as a PEP 440 pre-release (X.Y.Z.devN), so a plain pip install never selects it and pip install --pre does. The CLI team is yanking the eleven plain dev versions 0.26.3 to 0.26.11, after which a plain install gives the release, 0.26.0, until 0.27.0. sgit update follows the channel: a dev install moves to the newest pre-release, a release install to the newest release, --stable pins the newest release. The code is 0.26.11's, with two comment and wiring changes. Reviewed by cli.build: 0.26.12.dev0 is on PyPI; the yank had not happened when this was written. BR-4 resolved once it has.

sgit-ai 0.26.11: doctor shows signing; the signature gate exempts the empty first commit

Dev build of 28 October 2026, from the CLI's dev at 66f7e0d4. sgit doctor gains a Signing block (whether signing is on and why, format, key, programs, allowed-signers and revocation files); check verify --require-user-signature exempts only a vault's empty first commit, so the gate can pass on a vault whose every content commit is signed, and --limit N no longer checks N + 1 commits. The last plain build on PyPI before dev builds became pre-releases. Reviewed by cli.build: every check from 0.26.9 and 0.26.10 holds; doctor's block checked; the gate exemption not tested.

2026-10-28 · gooddev build

sgit-ai 0.26.10: sign commits and tags with your own key; the line differ is Git's

Dev build of 28 October 2026, from the CLI's dev at bbc51d9f. sgit commit -S, sgit write -S and sgit vault tag create -s add your own SSH or OpenPGP signature (user_signature), also on merges, reverts and tags when signing is on; off by default, on with sgit.gpgSign. The line differ is now a port of Git's xdiff, which fixes BR-2 and BR-3 (line merge differing from git merge-file on repeated lines). Reviewed by cli.build. Signed commits are read by clients from 0.20.0 to 0.26.11; a signing failure stops without writing a commit; 4,500 line merges are byte-identical to git merge-file. BR-2 and BR-3 closed. Open: BR-8 (a failed signing leaves two unreferenced objects).

2026-10-28 · good · BR-2, BR-3 closed · BR-8 lowdev build

sgit-ai 0.26.9: a push of any size uploads every commit (BR-1 fixed)

Dev build of 28 October 2026, from the CLI's dev at 9345a1fc. Fixes BR-1, the high finding in every build since at least 0.26.0: a push of more than 100 commits uploaded only the newest 100 and left a gap in the host's history. Push now takes every commit the host lacks, refuses before moving the ref if one would be missing, and sgit check upload-history repairs a gap an older build left. Reviewed by cli.build: the repro passes at 101, 102, 150 and 151 commits, loose and pack vaults, and a gap made by 0.26.8 is repaired from the clone that holds the commits. BR-1 closed.

2026-10-28 · good · BR-1 closeddev build

sgit-ai 0.26.8: history, blame and search; renames found as Git finds them

Dev build of 28 October 2026, from the CLI's dev at bc904c1b, and what a plain pip install gives today. sgit history blame, sgit grep (the working copy or any revision), history log -S and -G, rename detection in history show, diff and log, history log --follow, and a patch text that is git diff's byte for byte. Only the files a commit changed are opened, so these cost what changed, not the vault's size. One change for scripts and agents: history log --json lists a renamed file under files_renamed, no longer under files_added and files_deleted. Reviewed by cli.build. 5,436 unit and security tests pass. Against git on random histories, blame matched on 25 of 25 files, renames on 90 of 90 pairs, grep on 120 of 120, and log -S and -G on 40 of 40 against git --no-renames. Vaults made by 0.20.0 to 0.26.0 open. Maturity good. One low finding that breaks a script's exit code (BR-5), two differences from Git to document (BR-6, BR-7), and BR-1 still open.

2026-10-28 · good · BR-5 to BR-7 low · BR-1 open (all builds)dev build

sgit-ai 0.26.7: verify the signer's own SSH or OpenPGP signature on commits and tags

Dev build of 28 October 2026, from the CLI's dev at 0d486aaf. A commit or tag can carry its signer's own SSH or OpenPGP signature (user_signature, Git's gpgsig) beside the per-clone signature every commit already has, and this build checks them, with Git's verdicts and Git's trust files. sgit check verify, history log --show-signature, history show --show-signature and vault tag show report them. Nothing in the CLI can make one yet (sgit commit -S was written and parked until the web UI confirms the signing-bytes rule). Reviewed by cli.build. 5,235 unit and security tests pass. Old vaults and old clients are untouched; 0.26.0, 0.26.3 and 0.26.6 read, verify, fsck and push over commits that carry the new member. Maturity good. BR-1 is still open.

2026-10-28 · good · verify only · BR-1 open (all builds)dev build

sgit-ai 0.26.6: commit some paths, commit some hunks, push with uncommitted changes

Dev build of 28 October 2026, from the CLI's dev at 036e33b5, and what a plain pip install gives today. sgit commit takes paths, as git commit -- paths does, and leaves every other change on disk. sgit commit -p picks hunks interactively; agents use --list-hunks and --hunk ID, with ids that refuse to pick a different hunk once the file has changed. sgit push no longer refuses uncommitted changes. One behaviour change for scripts: with -m, extra words are now paths. Reviewed by cli.build. 5,144 unit and security tests pass. commit with paths matched Git in 40 random cases, and hunk commits matched git apply --cached in 60. Maturity good. One high finding, in every build since at least 0.26.0: a push of more than 100 commits leaves a gap in the host's history (BR-1).

2026-10-28 · good · BR-1 open (all builds)dev build

sgit-ai 0.26.5: line-level merge, opt-in

Dev build of 28 October 2026, from the CLI's dev at 43e1889c. sgit pull --merge lines and sgit branch merge --merge lines merge a file both sides changed line by line, as Git does, with Git's conflict markers in the file and --conflict diff3 for the base too. The default does not change: whole-file .conflict copies. Reviewed by cli.build. 5,030 tests pass and the four end-to-end checks hold. In 18,000 random merges against git merge-file, all 8,925 with unique lines were byte-identical. Where lines repeat, 2 of 4,544 code-like merges came out clean where Git reports a conflict (BR-2), and 0.9% placed conflict blocks differently (BR-3). Maturity good for an opt-in feature: review line-merged files before pushing.

2026-10-28 · good, opt-in · BR-2, BR-3dev build

sgit-ai 0.26.4: commit messages up to 64 KB

Dev build of 28 October 2026, from the CLI's dev at c495b40e. A commit message longer than 740 bytes used to fail with a raw ValueError, after the commit's blobs and trees were written; Git has no limit. The default limit stays 740 bytes, now refused before anything is written. A vault with the long-messages feature takes up to 64 KiB, and every client reads messages up to 1 MiB, the web UI's. Turning the feature on raises the vault's gate to 0.26.4, so an older sgit is told to update. Reviewed by cli.build. All checks held, including the refusal of 0.26.0 and 0.26.3 clients with a clear message. Maturity good. Wait for the 0.27.0 release before turning long-messages on in a vault that agents on 0.26.0 still use.

2026-10-28 · gooddev build

sgit-ai 0.26.3: Git-parity phase 0, merges made safe, and dev builds on PyPI

Dev build of 28 October 2026, from the CLI's dev at 16c46e89, and the first published as a plain version. It fixes the bugs the seven Git-parity designs found. sgit commit during an unresolved merge put the .conflict files into the vault; it now refuses. status shows a merge in progress. Identical content on both sides is no longer a conflict. Merges and pushes on forks deeper than 200 commits work. A nested vault is never committed. Object files are written atomically. Merges, writes and sparse commits rebuild only the changed folders. From this build, every dev merge is published as X.Y.N, and a plain pip install takes the newest. Reviewed by cli.build. 4,921 tests pass and every fix held, including a 250-commit fork that 0.26.1 merged against an empty base. Maturity good. One decision for Dinis Cruz: plain installs now get dev builds (BR-4).

sgit-ai 0.26.2.dev0: the Git-parity roadmap and seven designs, no code change

Pre-release of 28 October 2026, from the CLI's dev at 926c076d. The code is 0.26.1's; only the version differs. It carries the CLI team's Git-parity roadmap, sgit at parity with Git the client and then more on top, and seven designs: line merge and cherry-pick, signing with your own key, partial commits and hooks, renames, blame and grep, bisect, worktree, and rebase. All are published here as research. Reviewed by cli.build: the package matches its tag, and the 0.26.1 checks hold.

2026-10-28 · no code changepre-release

sgit-ai 0.26.1.dev0: pack index verify 120 times faster, and a new pack vault's gate fixed

Pre-release of 27 October 2026, from the CLI's dev at b9c8baac. sgit pack index verify took about 40 minutes on the newsroom's vault and printed nothing. It is now about 300 times faster, prints a line per pack, and --last N checks only the newest packs. A new pack vault is gated at what its features need, 0.24.0, not at the creating build's version, which fixes R3-2. sgit update gains --stable. Reviewed by cli.build. 4,752 tests pass. On 8,000 files and 6 packs, verify went from 82.9 s on 0.26.0 to 0.69 s. A new pack vault reads min_client 0.24.0. Maturity good. R3-1 is still open.

On 0.26.7 and 0.26.8 the 18 end-to-end checks above all pass, and P1 still fails. Their own checks are on their pages: signed commits read by 0.26.0, 0.26.3 and 0.26.6 (S1–S4); blame, grep, log -S and rename detection against git (H1–H6); and vaults made by 0.20.0, 0.22.0, 0.24.0 and 0.26.0, in normal and pack mode, opened by 0.26.8.

On 0.26.9 to 0.26.11 the 19 end-to-end checks pass, P1 included (BR-1 fixed); 4,500 line merges are byte-identical to git merge-file (BR-2 and BR-3 fixed); signed commits are read by clients from 0.20.0 to 0.26.11 (0.26.10); a gap made by 0.26.8 is repaired by check upload-history, loose and pack.

Four focused checks:

  • Line merge against git merge-file: 18,000 random three-way merges, in both merge styles. All 8,925 with unique lines were byte-identical. For the rest see BR-2.
  • Cross-version on one host: 0.26.6 against 0.26.0 and against 0.26.3, in both directions.
  • R3-1: re-run on 0.26.6.
  • pack index verify speed: 0.26.0 against 0.26.1.
