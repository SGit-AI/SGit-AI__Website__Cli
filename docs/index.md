# The sgit CLI documentation

Read the first section in order; the rest when you need it. ## Get started {#start}

- [sgit and Git: what only sgit does, what both do, and where Git is ahead](../docs/sgit-and-git.md): The row-by-row comparison, checked against sgit-ai 0.26.0 and the dev builds after it. Twelve things Git has no equivalent for, each with the command and Git's nearest answer: a host that reads nothing, read keys that work from any static host, custody without access, writes without reads, one folder by byte ranges from plain storage, indexes the writer ships encrypted and signed, policy the vault carries, rewinds refused by name, a secret guard, key rotation, a computable cache, files sealed to a person. Fifteen things both have, with what differs. Where Git is ahead: line-level merge and partial commits shipped in the dev builds of 28 October; the rest of the CLI team's Git-parity roadmap is designed, with sizes in days. GitHub's features move to a future server. And the six things zero knowledge rules out, each with its substitute.
- [What is sgit](../docs/what-is-sgit.md): sgit is git for encrypted vaults: how it works, what makes it different from git, and the ecosystem around it.
- [Installation](../docs/installation.md): Install sgit with pip, verify with sgit doctor, upgrade with sgit update. Python 3.11+, two runtime dependencies.
- [Quickstart](../docs/quickstart.md): From zero to a synced, encrypted, versioned vault in five minutes: create, commit, push, clone, pull.
- [sgit for git users](../docs/sgit-for-git-users.md): The Rosetta stone: every git command mapped to its sgit equivalent, plus the three deliberate differences.
- [The two-branch model](../docs/two-branch-model.md): sgit's central idea: private clone branches per machine or agent, shared named branches, and explicit publishing.
- [When NOT to use sgit](../docs/limitations.md): The honest page: sgit's edges, stated plainly, plus the current roadmap gaps.

## Guides {#guides}

- [Partial clones: a folder scope and a history depth](../docs/partial-clones.md): sgit clone --path holds one folder and carries the rest by id; --depth holds the newest commits only. Measured on a 600-commit vault: one folder in 14 s against 80 s for the whole vault. The rules, widening with sgit fetch, the commands that need a full clone, and the two edges.
- [Pack mode: a playbook for agents](../docs/pack-mode-for-agents.md): Everything an agent needs to use sgit pack vaults (sgit-ai 0.24.0 and later) in a project, as recipes to follow in order. Decide whether a vault should be a pack vault; create one, or convert a copy of an existing vault and cut a team over to it; the daily loop and what its output should look like; who compacts, when, and how; the patterns for CI jobs, many agents, read-only readers and throwaway vaults; the health checks; every error message an agent will meet, with what to do; what never to do; and a block to paste into an agent's own instructions.
- [History integrity: the format gate, verifying signatures, and rewinds](../docs/history-integrity.md): sgit vault format (format 2, 128-bit ids, --min-client), who can open a raised vault and what old clients say, the shared branch index, rewind detection and --accept-rewind, sgit check verify, signatures-required and what a signature proves, and a checklist for raising a vault. For sgit-ai 0.21.0.
- [Working with AI agents](../docs/agents.md): The agent-facing surface: sgit write, --json everywhere, the clone modes including scoped and shallow clones, the session pattern, and multi-agent collaboration.
- [Agents sharing one vault](../docs/agents-sharing-one-vault.md): The loop for a team of agents on one vault with sgit-ai 0.18.0: a scoped shallow clone per session, status before commit, push that pulls first, and the full table of what a pull does with uncommitted work: kept when untouched, refused by name when it would be overwritten.
- [Sending messages between vaults](../docs/vault-messaging.md): How two vaults exchange encrypted messages without sharing a vault key and without the sender holding an account: append lanes addressed by a token, composed with PKI. Worked example in CLI, curl and sg.append, with the one step that is not yet wired marked PROPOSED.
- [Append-lane messaging between agents that hold no one else's vault key](../docs/append-lane-messaging.md): The write-up of two-way, signed and encrypted messaging between agents over sgit's append lanes, as two teams ran it on 25 and 26 September 2026: per-session signing keys with a pinned key registry on the sender's own site, ephemeral inbox vaults for agents that keep no secret, the flows, security properties, threat model, HTTP calls as observed, eleven places sgit.ai's docs differed, and recommendations for sgit. Relayed by sgit.newsroom.sgit.ai.
- [Self-hosting a vault server for agents](../docs/self-host-for-agents.md): Encrypted memory for agents in VMs, containers, a Mac mini or ephemeral jobs: run the SG/Send container with an access token and a storage folder, create the vault, the agent's clone-work-push entry point, Docker Compose, Kubernetes manifests, the cloud, a second server, what the server holds, and the errors you may meet (--endpoint, mcp<2, port 8080).
- [Send a vault key to the registry](../docs/send-a-vault-key.md): For an agent that holds SG/Send vault keys and was given this page, an inbox vault id and an append token: the rules (never display a key, never improvise a route), the vault-key-handover/v1 payload, the registry's public key and endpoint, a sender script that pins the key's fingerprint, what to do afterwards and on a 404. The id and the token are never published.
- [sgit-ai 0.25.0 release notes: large vaults](../docs/update-to-0-25-0.md): Release notes for sgit-ai 0.25.0, for people and agents. On a large vault, the cost of a command now follows the change, not the vault. On a vault of 76,000 files a one-file commit went from 29 minutes to under 5 seconds and a status from 71 seconds to about 4. What changed (trees read as JSON, the flattened head cached, a linear and incremental tree builder, a scan cache keyed like git's index, no tree walk when a push's server has nothing new, history log by tree diff), the data-loss bug a review found in the first version of the scan cache and how it was closed, the two new cache files and what they hold, and what is still slow. Nothing changes on the server or in a vault's format.
- [Using sgit from Claude on a Team or Enterprise plan: the network allowlist](../docs/how-to/claude-team-egress.md): On Claude Team and Enterprise plans an Owner sets the code sandbox's network access for the whole organisation, and the default blocks every sgit host. Which domains to allow (apex domains explicitly), how to check from inside a session, how a proxy's CONNECT 403 differs from a server outage, and why web fetch can read sgit.ai while the shell cannot.
- [sgit-ai 0.24.0 release notes: pack mode](../docs/update-to-0-24-0.md): Release notes for sgit-ai 0.24.0, for people and agents. Pack mode is new and opt-in: a vault whose objects travel as zips, cloned in a handful of requests whatever its history, with files compressed before they are encrypted. The commands (init --packs, pack import, export, compact, ls, stats, verify), what was measured, the gate that refuses older clients by name, what does not work on a pack vault yet, the two transport changes every vault gets, and how the release was reviewed. Normal vaults behave as before.
- [sgit-ai 0.26.0 release notes: pack indexes, selective working copies, the pack store](../docs/update-to-0-26-0.md): Release notes for sgit-ai 0.26.0, for people and agents. Every push to a pack vault now writes an index pack beside its data pack, so readers stop walking trees. A pull plans its fetch from the indexes, and history log reads change lists. A clone can skip writing the working copy, and an agent then checks out only the files it needs. A clone can keep the packs in place instead of unpacking hundreds of thousands of objects. A clone of one folder takes that folder by byte ranges. On a 76,000-file vault, a full clone fell from about two minutes to one, a no-checkout clone takes about 28 seconds, a one-folder clone under 3 seconds against 36, and history log half a second against three. The new agent loop, the commands, the compatibility rules (a pack vault created by 0.26.0 needs 0.26.0), what is on disk, and what is still slow. Nothing changes on the server.
- [Update sgit-ai to 0.21.0](../docs/update-to-0-21-0.md): For an agent team: sgit update, what now refuses and what to do (symlinks, unreadable files, SGIT_DEFAULT_BASE_URL, key zips, branch names, rewinds, signatures), the new history commands (undo, reflog, amend, revert --as-commit, shorthand, log filters), signed tags, --force-with-lease, notes for vault owners and mixed 0.20/0.21 teams. Covers 0.19.0 and 0.20.0. Published 11 October 2026.
- [Update sgit-ai to 0.18.0](../docs/update-to-0-18-0.md): Five minutes for an agent team: sgit update, check the version, change the clone command to --path and --depth, and what to do when a pull is refused. Published 7 October 2026.

The last plain build on PyPI before dev builds became pre-releases. Reviewed by cli.build: every check from 0.26.9 and 0.26.10 holds; doctor's block checked; the gate exemption not tested.
- [sgit-ai 0.26.10: sign commits and tags with your own key; the line differ is Git's](../builds/0-26-10.md): Dev build of 28 October 2026, from the CLI's dev at bbc51d9f. sgit commit -S, sgit write -S and sgit vault tag create -s add your own SSH or OpenPGP signature (user_signature), also on merges, reverts and tags when signing is on; off by default, on with sgit.gpgSign. The line differ is now a port of Git's xdiff, which fixes BR-2 and BR-3 (line merge differing from git merge-file on repeated lines). Reviewed by cli.build. Signed commits are read by clients from 0.20.0 to 0.26.11; a signing failure stops without writing a commit; 4,500 line merges are byte-identical to git merge-file. BR-2 and BR-3 closed. Open: BR-8 (a failed signing leaves two unreferenced objects).
- [sgit-ai 0.26.9: a push of any size uploads every commit (BR-1 fixed)](../builds/0-26-9.md): Dev build of 28 October 2026, from the CLI's dev at 9345a1fc. Fixes BR-1, the high finding in every build since at least 0.26.0: a push of more than 100 commits uploaded only the newest 100 and left a gap in the host's history. Push now takes every commit the host lacks, refuses before moving the ref if one would be missing, and sgit check upload-history repairs a gap an older build left. Reviewed by cli.build: the repro passes at 101, 102, 150 and 151 commits, loose and pack vaults, and a gap made by 0.26.8 is repaired from the clone that holds the commits. BR-1 closed.
- [sgit-ai 0.26.8: history, blame and search; renames found as Git finds them](../builds/0-26-8.md): Dev build of 28 October 2026, from the CLI's dev at bc904c1b, and what a plain pip install gives today. sgit history blame, sgit grep (the working copy or any revision), history log -S and -G, rename detection in history show, diff and log, history log --follow, and a patch text that is git diff's byte for byte. Only the files a commit changed are opened, so these cost what changed, not the vault's size. One change for scripts and agents: history log --json lists a renamed file under files_renamed, no longer under files_added and files_deleted. Reviewed by cli.build. 5,436 unit and security tests pass. Against git on random histories, blame matched on 25 of 25 files, renames on 90 of 90 pairs, grep on 120 of 120, and log -S and -G on 40 of 40 against git --no-renames. Vaults made by 0.20.0 to 0.26.0 open. Maturity good. One low finding that breaks a script's exit code (BR-5), two differences from Git to document (BR-6, BR-7), and BR-1 still open.
- [sgit-ai 0.26.7: verify the signer's own SSH or OpenPGP signature on commits and tags](../builds/0-26-7.md): Dev build of 28 October 2026, from the CLI's dev at 0d486aaf. A commit or tag can carry its signer's own SSH or OpenPGP signature (user_signature, Git's gpgsig) beside the per-clone signature every commit already has, and this build checks them, with Git's verdicts and Git's trust files. sgit check verify, history log --show-signature, history show --show-signature and vault tag show report them. Nothing in the CLI can make one yet (sgit commit -S was written and parked until the web UI confirms the signing-bytes rule). Reviewed by cli.build. 5,235 unit and security tests pass. Old vaults and old clients are untouched; 0.26.0, 0.26.3 and 0.26.6 read, verify, fsck and push over commits that carry the new member. Maturity good. BR-1 is still open.
- [sgit-ai 0.26.6: commit some paths, commit some hunks, push with uncommitted changes](../builds/0-26-6.md): Dev build of 28 October 2026, from the CLI's dev at 036e33b5, and what a plain pip install gives today. sgit commit takes paths, as git commit -- paths does, and leaves every other change on disk. sgit commit -p picks hunks interactively; agents use --list-hunks and --hunk ID, with ids that refuse to pick a different hunk once the file has changed. sgit push no longer refuses uncommitted changes. One behaviour change for scripts: with -m, extra words are now paths. Reviewed by cli.build. 5,144 unit and security tests pass. commit with paths matched Git in 40 random cases, and hunk commits matched git apply --cached in 60. Maturity good. One high finding, in every build since at least 0.26.0: a push of more than 100 commits leaves a gap in the host's history (BR-1).
- [sgit-ai 0.26.5: line-level merge, opt-in](../builds/0-26-5.md): Dev build of 28 October 2026, from the CLI's dev at 43e1889c. sgit pull --merge lines and sgit branch merge --merge lines merge a file both sides changed line by line, as Git does, with Git's conflict markers in the file and --conflict diff3 for the base too. The default does not change: whole-file .conflict copies. Reviewed by cli.build. 5,030 tests pass and the four end-to-end checks hold. In 18,000 random merges against git merge-file, all 8,925 with unique lines were byte-identical. Where lines repeat, 2 of 4,544 code-like merges came out clean where Git reports a conflict (BR-2), and 0.9% placed conflict blocks differently (BR-3). Maturity good for an opt-in feature: review line-merged files before pushing.
- [sgit-ai 0.26.4: commit messages up to 64 KB](../builds/0-26-4.md): Dev build of 28 October 2026, from the CLI's dev at c495b40e. A commit message longer than 740 bytes used to fail with a raw ValueError, after the commit's blobs and trees were written; Git has no limit. The default limit stays 740 bytes, now refused before anything is written. A vault with the long-messages feature takes up to 64 KiB, and every client reads messages up to 1 MiB, the web UI's. Turning the feature on raises the vault's gate to 0.26.4, so an older sgit is told to update. Reviewed by cli.build. All checks held, including the refusal of 0.26.0 and 0.26.3 clients with a clear message. Maturity good. Wait for the 0.27.0 release before turning long-messages on in a vault that agents on 0.26.0 still use.
- [sgit-ai 0.26.3: Git-parity phase 0, merges made safe, and dev builds on PyPI](../builds/0-26-3.md): Dev build of 28 October 2026, from the CLI's dev at 16c46e89, and the first published as a plain version. It fixes the bugs the seven Git-parity designs found. sgit commit during an unresolved merge put the .conflict files into the vault; it now refuses. status shows a merge in progress. Identical content on both sides is no longer a conflict. Merges and pushes on forks deeper than 200 commits work. A nested vault is never committed. Object files are written atomically. Merges, writes and sparse commits rebuild only the changed folders. From this build, every dev merge is published as X.Y.N, and a plain pip install takes the newest. Reviewed by cli.build. 4,921 tests pass and every fix held, including a 250-commit fork that 0.26.1 merged against an empty base. Maturity good. One decision for Dinis Cruz: plain installs now get dev builds (BR-4).

The code is 0.26.1's; only the version differs. It carries the CLI team's Git-parity roadmap, sgit at parity with Git the client and then more on top, and seven designs: line merge and cherry-pick, signing with your own key, partial commits and hooks, renames, blame and grep, bisect, worktree, and rebase. All are published here as research. Reviewed by cli.build: the package matches its tag, and the 0.26.1 checks hold.
- [sgit-ai 0.26.1.dev0: pack index verify 120 times faster, and a new pack vault's gate fixed](../builds/0-26-1.md): Pre-release of 27 October 2026, from the CLI's dev at b9c8baac. sgit pack index verify took about 40 minutes on the newsroom's vault and printed nothing. ## Security {#security}

- [Security model](../security/index.md): sgit's zero-knowledge security model, precisely stated: the crypto stack, what the server can and cannot see, key strength, and the open security process.
- [Vault key management: where each key lives, and how it travels](../docs/key-management.md): The reference for sgit-ai v0.20.0: each kind of credential and where it belongs, how a key travels without entering a chat, giving a key to an agent when platforms have no per-session secrets, rotation with rekey and move, and the local alias store.
- [Vault credentials: what each one can do, and what its prefix declares](../docs/credentials.md): Two capabilities, a vault key that reads and writes and a read key derived from it one way, plus the five prefixes that declare which you are holding and whether it was meant to be published. Why sgit_public_read_ is the form for an open vault, why publishing one under sgit_private_read_ is a mislabel that an agent will correctly refuse, and why the word matters when the bytes are identical.
