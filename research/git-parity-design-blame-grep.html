2. Scope and non-goals

In scope

  • Rename detection: exact, basename and similarity passes, with -M[<n>], --no-renames and the 1,000 limit.
  • Where renames show: history diff (all modes), history show, history log --stat / --files / --patch / --json and the new history log --file <path> --follow.
  • For the merge: the pairing API that design 01 calls.
  • sgit history blame:
  • <rev>, -L (numeric, +N, -N, /regex/, repeatable)
  • -w, --first-parent
  • output: --porcelain, --line-porcelain, --json, -s, -e (show key id), --abbrev N
  • sgit grep (and sgit file grep):
  • match flags: -i -w -v -F -E -P -e
  • output flags: -n -c -l -L -o -q -h -H -A/-B/-C, --json
  • what is searched: working copy, <rev>, --untracked, pathspecs
  • Pickaxe: history log -S <string>, --pickaxe-regex, -G <regex>, combinable with --grep, --since, --until, --author and --file.
  • A prerequisite refactor: Vault__Diff stops decrypting every file of both commits (section 4.3).

Not in scope

  • Copy detection (-C, --find-copies-harder): a follow-up if asked.
  • More blame options:
  • --ignore-rev / --ignore-revs-file: optional, a follow-up; section 11, D12.
  • -M/-C inside blame (moved or copied lines within or between files).
  • -L :funcname, --incremental, --reverse, --since.
  • More grep options:
  • --and / --or / --not / (…) boolean expressions. Several -e patterns OR together, as in Git.
  • --recurse-submodules, -p / --show-function, --threads.
  • POSIX BRE (Git's default dialect); see D2.
  • Elsewhere:
  • renames in status (Git shows them only for staged changes; sgit has no staging area); D10.
  • any server-side search: impossible under zero knowledge, by design.
  • reading without a clone (--vault-key on a bare checkout is supported, as history log supports it; a no-clone network read is roadmap item "cat --vault-key").

3.3 sgit grep (also sgit file grep)

sgit grep [-i] [-w] [-v] [-F | -E | -P] [-n] [-c] [-l | -L] [-o] [-q] [-h | -H]
          [-A N] [-B N] [-C N] [-m N] [--untracked] [--text | -I] [--json] [--offline]
          [--vault-key KEY] [-d DIR]
          (<pattern> | -e <pattern>...) [<rev>...] [-- <pathspec>...]

Pattern and dialect

  • The pattern is a Python regular expression (D2): -E (ERE) and -P (PCRE) are accepted and mean the same thing.
  • -F takes the pattern literally.
  • Several -e options are ORed.
  • -i, -w and -v as in Git.

What is searched

  • With no <rev>: the working copy's files, filtered by the ignore rules status uses, plus --untracked untracked files. The bytes on disk are searched, never followed through a symlink.
  • With <rev> (any revision Vault__Revision resolves: HEAD, HEAD~2, a tag, a short id): that commit's tree, decrypted in memory.

Output

  • One line per match, as Git prints it:
  • working copy: path:line:text
  • a revision: <rev as typed>:path:line:text
  • -n adds line numbers.
  • -c prints path:count; -l the matching files; -L the files without a match; -o only the matched parts; -A/-B/-C context with -/-- separators as in Git; -m N stops after N matches per file.
  • -h/-H hide or show the file name.
  • A binary file (a NUL in its first 8,000 bytes, Git's rule; sgit's BINARY_CHECK_BYTES is 8,192 and is reused) prints Binary file <path> matches. -I skips binary files; --text searches them as text.

Pathspecs: after --, Git's basic form: a literal prefix (docs/, docs/a.md) or a glob with *, ? and […] (fnmatch on the full path, ** matching folders). Magic forms (:(exclude), :!) are not supported and are refused by name.

--json (grep_v1):

{"schema": "grep_v1", "rev": "", "pattern": ["five"],
 "matches": [{"rev": "", "path": "c.txt", "line": 5, "text": "five", "spans": [[0, 4]]}],
 "files_searched": 0, "binary_matches": ["img.png"],
 "skipped": {"not_checked_out": 0, "not_local": 0, "outside_scope": 0}}

Exit codes (D3):

CodeWhen
0At least one match (with -L: at least one file printed; with -q: a match, and nothing printed)
1No match
2Error: bad pattern, guard refusal, unknown revision, pathspec magic, outside scope

5. Design

5.1 Line differ: Vault__Line_Diff

One line differ for blame, -G, the unified diff and the merge.

  • Design 01 (diff3) needs matching blocks between base/ours and base/theirs. If design 01 specifies its own line differ, this design uses that class instead and the names below are aliases. There must be one implementation.

Interface

  • File: sgit_ai/core/actions/diff/Vault__Line_Diff.py, class Vault__Line_Diff(Type_Safe).
  • Fields:
  • ignore_whitespace : bool = False (-w: lines compared with all whitespace removed, as Git's -w);
  • max_cost : Safe_UInt = 0 (0 = the default bound below).
  • Methods:
  • split_lines(data: bytes) -> list — bytes.splitlines(keepends=True). A final line without \n stays distinct from the same text with one, as in Git ("\ No newline at end of file").
  • matching_blocks(a: list, b: list) -> list — [(a_start, b_start, length)], ascending, ending with the sentinel (len(a), len(b), 0), the same contract as difflib.SequenceMatcher.get_matching_blocks().
  • opcodes(a, b) -> list — [('equal'|'replace'|'delete'|'insert', i1, i2, j1, j2)] derived from the blocks.

Algorithm: Myers O((N+M)·D) greedy diff, the algorithm behind Git's default

  • Common prefix and suffix are stripped first, as xdiff does.
  • Lines are interned to integers (hash map of line → id; with -w, the key is the line with whitespace removed).
  • Linear-space divide and conquer (middle snake) above 10,000 lines.
  • When D passes a cost bound (default max(256, sqrt(N+M) * 16), xdiff's "heuristic" idea), it falls back to difflib.SequenceMatcher(None, a, b, autojunk=False) on the remaining window, so a pathological pair never runs quadratic for minutes.

Why not difflib alone

  • SequenceMatcher finds longest matching blocks, not a minimal edit script. With autojunk=True (the default) it treats lines that occur in more than 1% of a file over 200 lines as junk, and loses matches on files full of blank lines.
  • Blame attribution would then differ from Git's on common files.
  • difflib.unified_diff stays for printing hunks today. It is switched to opcodes() in step 3 so that the printed diff and blame agree.

Entry point (also the API design 01 consumes)

def detect(self, deleted: dict, added: dict, content_of=None) -> Schema__Rename_Result:
    """deleted/added: {path: flat entry} (the diff_trees / flatten shape: blob_id, size, content_hash, ...).
    content_of: callable(entry) -> bytes | None, the plaintext of an entry (None = not available).
    Without content_of only the exact pass runs. Never raises for a missing blob."""

Pass 1, exact (always, no limit):

  1. Group deleted by (content_hash, size), skipping entries without a content_hash.
  2. For each added path in sorted order, the candidates are the deleted paths with the same key not yet used. Pick the one with the same basename if any (Git's preference), else the first by path.
  3. Score 100, exact=True.
  4. A source pairs at most once. A second destination of the same content is an add (copies are out of scope).
  5. Empty files take part (Git 2.43 pairs a lone moved empty file; confirmed). With several empty files, only same-basename pairs are made, so empty files never pair at random. Test 9.1 R10 checks this against Git.

Pass 2, basename (needs content_of, no limit):

  1. Among unpaired paths, take basenames that occur exactly once among the remaining sources and exactly once among the remaining destinations.
  2. Score each such pair by similarity.
  3. Accept at min_basename_score = min_score + (100 - min_score) / 2 (75 at the default), Git's rule from 2.33.

Pass 3, inexact matrix (needs content_of):

  1. If len(src) > limit or len(dst) > limit and len(src) * len(dst) > limit * limit, skip the pass and set limit_hit=True (Git's too_many_rename_candidates).
  2. Else, for each destination, score every source that passes the size precheck, keep the best four (NUM_CANDIDATE_PER_DST, as Git), sort all kept pairs by score descending then by destination path, and accept greedily, each path once, at score >= min_score.

similarity(src: bytes, dst: bytes) -> int follows Git's diffcore-delta.c and estimate_similarity.

  1. Size precheck: with max_size = max(len) and delta = abs(len(src) - len(dst)), return 0 when max_size * (100 - min_score) < delta * 100. A file cannot be a 50% rename of one under half its size.
  2. Chunking (hash_chars): chunk each buffer. A chunk ends after a \n or after 64 bytes. For a text buffer (no NUL in the first 8,000 bytes), a \r directly before \n is skipped. Key each chunk by its bytes; the count is the chunk's length.
  3. Count: copied = Σ min(src_count[k], dst_count[k]) over keys present in both.
  4. Score: copied * 100 // max_size, truncated as Git prints it (Git computes on MAX_SCORE = 60000 and prints score * 100 / MAX_SCORE; the integer percent is the same up to rounding). Test 9.1 R4 compares with Git within ±1.
  5. Empty src or dst: 0 (an empty file is only ever an exact rename).

content_of cost control

  • Callers pass Vault__Blob_Reader.content (5.3).
  • Blobs larger than RENAME_MAX_BYTES = 4 MB (Git uses big_file_threshold 512 MB, but our reads are decrypts) are scored by exact pass only and counted in unread.
  • In-memory chunk maps are memoised per blob id for one detect call.

Trust:

  • content_hash is the committer's claim. For display (diff, show, log), pairing by the claim is accepted: a lying writer (A3) can make --stat show a false rename and nothing else.
  • For the merge, design 01 must call detect(..., content_of=...) with verify_exact=True (a keyword on detect). Each exact pair is then confirmed by decrypting both blobs and comparing bytes, and an unconfirmed claim drops to pass 3.

Coordination note for design 01

  • three_way_merge (sgit_ai/core/actions/merge/Vault__Merge.py:14) compares blob ids, and blob ids are random per write (4.1). The same content written independently on both sides is reported as a conflict today (ours_bid != theirs_bid). Comparing content_hash + size (verified when it matters) fixes that.
  • The merge's rename pairs: detect(base_deleted_in_ours, ours_added) and the same for theirs.

5.3 Reading content: Vault__Blob_Reader

Purpose: one place that turns a flat entry into plaintext, for renames, blame, grep, pickaxe and the pruned diff.

Interface

  • File: sgit_ai/core/actions/history/Vault__Blob_Reader.py, class Vault__Blob_Reader(Type_Safe).
  • Fields:
  • crypto, obj_store, read_key : bytes, vault_id : str, sg_dir : str;
  • api : object = None (set only when a remote is configured: the _on_demand_api rule);
  • offline : bool = False;
  • memo_bytes : Safe_UInt = 64 MB;
  • counters blobs_read, blobs_fetched, blobs_missing (Safe_UInt; reported in --json stats and used by the tests instead of a counting double).

Behaviour

  • content(entry) -> bytes | None:
  1. A local object → obj_store.load (this also reads from a --pack-store clone by offset).
  2. Else, with api and not offline → fetch with api.read / read_large, _save_verified (verified by content address before it is written, as sparse_cat does), then load.
  3. Else → None and blobs_missing += 1.
  • Decryption errors propagate (a wrong key must fail loudly, as history log does with InvalidTag).
  • prefetch(entries: list) -> None: one api.batch_read for every missing blob in the list, in batches of the existing batch size. Blame and grep call it before walking, so a sparse clone makes a handful of requests instead of one per file.
  • The memo is an LRU keyed by blob id up to memo_bytes of plaintext, in memory only.

5.6 Blame: Vault__Blame

Classes

  • File: sgit_ai/core/actions/history/Vault__Blame.py, class Vault__Blame(Type_Safe).
  • Fields: crypto, api : object = None, ignore_whitespace : bool, first_parent : bool, follow_renames : bool = True, text : bool = False, offline : bool = False.
  • Schemas (sgit_ai/schemas/history/):
  • Schema__Blame_Line: final_line : Safe_UInt, orig_line : Safe_UInt, commit_id : Safe_Str__Commit_Id, orig_path : Safe_Str__Content_Path, text : Safe_Str__Diff_Text;
  • Schema__Blame_Commit: timestamp_ms, author : Safe_Str__Diff_Text, author_key_id, summary : Safe_Str__Diff_Text, boundary : bool, previous_id, previous_path;
  • Schema__Blame_Result: schema = 'history_blame_v1', path, rev, boundary_reason, commits : dict[Safe_Str__Commit_Id, Schema__Blame_Commit], lines : list[Schema__Blame_Line], stats.

Entry point: blame(directory, path, rev='', ranges=None) -> Schema__Blame_Result.

Algorithm (Git's blame.c, assign_blame / pass_blame, simplified to what we support):

  1. Start.
  • Resolve rev (default the clone's HEAD) with Vault__Revision.
  • entry = path_history.entry_at(commit.tree_id, path).
  • None, or a folder → exit 1 with path not found in <rev>.
  • Content via Vault__Blob_Reader. Binary (NUL rule) without --text → exit 1 with binary file: pass --text to blame it line by line.
  • Lines via Vault__Line_Diff.split_lines. -L ranges are resolved on this content.
  1. Entries.
  • A blame entry is (final_start, count, suspect_start), held per origin (commit_id, path, entry).
  • Start: one entry per -L range, all on origin (rev, path, entry).
  • Origins wait in a priority queue keyed by generation number (from the pack index's commit-gen, or Vault__Pack_Index.generation_of with its local memo) and then timestamp_ms, highest first. Git's queue orders by commit date; generation avoids clock skew between agents and gives the same order on linear history.
  1. Process the next origin O (commit C, path P, entry E):
  • Parents: C's parents in order; with --first-parent, only the first.
  • Boundary. C has no parents; or C is a shallow boundary (Vault__Scope.is_boundary); or C's parent commit object is not local and cannot be fetched. Then every entry of O is final and C is marked boundary. boundary_reason is set to shallow / offline when that is the cause.
  • Find each parent's version. E_p = entry_at(parent.tree_id, P).
  • If None and follow_renames: run Vault__Renames.detect on diff_trees(C.tree, parent.tree) restricted to destination P (all deleted paths as sources, only P as destination; the limit counts 1 × sources, so the inexact pass always runs). A pair gives (P_p, E_p).
  • If still None, that parent does not hold the file.
  • Whole pass. If some parent has same_at(C.tree, parent.tree, …) for the file (same blob, or same content_hash + size), all of O's entries move to that parent's origin unchanged, without a diff. Git does this for an identical parent, and it is the step that makes blame cheap on a long history. Done with O.
  • Diff pass. Otherwise, for each parent holding the file, in order:
  • Diff parent content → C content with Vault__Line_Diff (honouring -w).
  • For every equal block (i, j, n), the overlap of each remaining entry's suspect range [j, j+n) moves to the parent's origin with suspect_start remapped to i + (s - j). Entries are split at block edges.
  • Lines left after all parents stay blamed on C.
  • At a merge, lines equal to the first parent go there first and the rest are offered to the next parent: Git's order.
  • Merge origins. A parent origin already in the queue (same commit, same path) gets the entries appended, so a commit is diffed once per path.
  1. Finish. Final entries are sorted by final_start and expanded to lines with orig_line = suspect_start + k. Commit metadata is collected:
  • author: the branch name from the branch index (_branch_names as in CLI__Vault, :2338), else the key id;
  • summary: the first line of the decrypted message;
  • previous: the first parent holding the file and its path.

Pack index acceleration (step 9).

  1. When the head's snapshot index is local and verified (open_index(kind='snapshot')), read file-commits:<shard_of_path(P)> for P.
  2. The listed commits are the plan: the walk visits only them, and treats each unlisted stretch between two listed commits as unchanged for P.
  3. Because the snapshot index is anchored only at the root (TM-R42), the plan is checked as it is used. For each step from listed commit C to the next listed ancestor C' on the walk, same_at(parent(C).tree, C'.tree, P) must hold: the file must really be unchanged across the skipped stretch.
  4. One failed check drops the plan for the rest of the command (noted once on stderr: index plan for <path> did not match the trees; walking) and the walk continues commit by commit.
  5. A lying index can therefore cost time, never a wrong attribution.
  6. Renames end the plan at the commit where the path was added. The plan of the old path is read from its own shard.

Partial clones and limits:

  • Scoped: P outside scope.contains_path → exit 1 with '<path>' is outside this clone's folders (<list>); widen with: sgit fetch <folder>.
  • Shallow: boundary as above.
  • Sparse / selective: blobs are fetched on demand (Vault__Blob_Reader.prefetch with the blobs of the planned commits when a plan exists).

5.7 Grep: Vault__Grep

Classes

  • File: sgit_ai/core/actions/history/Vault__Grep.py, class Vault__Grep(Type_Safe).
  • Fields: crypto, api : object = None, options as typed fields:

Engine

  1. Compile. One Python re pattern: -F escapes each pattern; several patterns join as (?:p1)|(?:p2); -w wraps as (?<![\w])(?:…)(?![\w]) (Git's word rule: the match must start and end at a word boundary of [A-Za-z0-9_]; test 9.3 G6 checks edge cases against Git); -i adds re.IGNORECASE.
  • Every pattern is checked first by Vault__Regex_Guard.check(pattern) (5.9).
  • Matching is on str: content is decoded utf-8 with errors='surrogateescape', so any byte sequence round-trips and non-UTF-8 files still match byte-for-byte on their ASCII parts.
  1. Prefilter per file. One search over the whole decoded text; no match → skip the file without splitting lines. With -v, -L or -c, the prefilter is skipped (they need every line). That keeps the common case at C speed: one regex scan per file.
  2. Lines. On a hit, iterate lines with offsets (str.splitlines(keepends=True) once), collect matches, context windows and -m cut-off, and emit Schema__Grep_Match rows in path order then line order.
  3. Binary. NUL in the first 8,192 bytes:
  • default → one Binary file <path> matches row when the prefilter hits;
  • -I → skipped;
  • --text → treated as text.

5.8 Pickaxe: Vault__Pickaxe

Interface

  • File: sgit_ai/core/actions/history/Vault__Pickaxe.py, class Vault__Pickaxe(Type_Safe).
  • Fields: mode : Safe_Str ('S' or 'G'), needle : Safe_Str__Grep_Pattern, regex : bool, ignore_case : bool, only_path : Safe_Str__Content_Path = None, plus Vault__Blob_Reader and Vault__Line_Diff.
  • Method: matches(commit, parent, changes) -> list[path], where changes is the commit's change list (the index's changes member when available, else diff_trees).

Rules

  • -S: for each changed file (A, M, D; restricted to only_path), count occurrences in old and new content (literal: str.count, non-overlapping as Git; --pickaxe-regex: len(re.findall)). Different counts → the path matches. Binary files are counted too (Git's -S does). An added file counts against 0 and a deleted file against 0.
  • -G: run the line diff of old → new and test each inserted or deleted line with re.search. Binary files are skipped unless --text (Git's -G rule).
  • Merges (more than one parent): skipped, counted in the note.
  • Wiring:
  • _print_log (CLI__Vault.py:2274) gains a pickaxe branch: walk the DAG newest-first as the filtered log does.
  • For each non-merge commit get changes from _index_changes_provider or diff_trees, apply the other filters first (cheap: message, date, author), then Vault__Pickaxe.matches.
  • Stop once -n (default 50) matches are printed.
  • --stat shows the matching files only, or all with --pickaxe-all.

Blame and grep

  • [ ] sgit history blame <file> on a 5-commit history equals git blame line for line (commit mapping by message).

Pickaxe
