2. The deferrals

  • M4, at before the central directory: agreed. On this vault the snapshot index (32.6 MB) is larger than the directory a scoped clone reads (10.7 MB), so at only pays once the index can be read selectively, or answered by the server (Phase 4). The half that is done, one presigned URL per pack, was the cheap win.
  • L4, the optional member set for blob-paths and file-commits: decide it with Phase 4, with the scoped reader that needs neither. Until then, the size is the price of every clone of a vault of many small files. On the newsroom's 1.22 GB snapshot it is a few per cent.

3. Small things left

#NoteSuggestion
N1A --no-checkout or bare pack clone now skips both the tree walk and the working-copy step's presence check, which runs only where files are written. A pack with refused members would let such a clone finish silently, and the next sgit checkout would find the gaprun the presence check (every folder tree and blob of the head, against the store's set) for every unscoped pack clone; it is a set lookup
N2A pack vault's first push writes a snapshot and no commit index, so history log always walks that commit (and diffs the root against nothing). On a short history that is the whole cost: 3.4 s on the 76,000-file vaulttake the first commit's counts from the snapshot index's flat member (every file is an A), or write a commit index for the first push too
N3INDEX_PLAIN_MAX is 1 GiB. The largest legitimate member, flat of a 228,000-file head, is about 50 MB64 or 128 MB is enough, and bounds a crafted member's memory to that
N4build_commit_members takes 2.0 s per push on a cold process (0.25 s warm) on the 76,000-file vaultfine for now; it is the flatten of the head, which a push usually has cached
