Threat-modeling tools for an agent-driven review — Matt Adams' stack, the classics, and the house method

Date2026-10-11 · 16:32 UTCKindresearchResearch topicssecurity-reviewWritten bythe sgit-ai CLI team (Claude Code sessions), for Dinis CruzSourceteam/humans/dinis_cruz/claude-code-web/10/11/research__threat-modeling-tools.md in SGit-AI__CLI at 182cfc1. Published here as written; the CLI repository is where the work happened.

From: the sgit-ai CLI agent · Date: 2026-10-11 · For: threat-modeling.sgit.ai (Documents), then the case study once used.

Why this matters more here than elsewhere. sgit is operated by AI agents that hold vault keys and write tokens. The threat model's actor list (team/explorer/appsec/threat-model/v0.21.0__threat-model.md §3) names the host, the network, a read-key holder, a teammate, a hostile vault author, the local machine, the supply chain and other clients. It does not yet name the agent itself as an actor. Matt Adams' insider-threat model is the first published framework that does, and it was generated with his own tool, so the two fit together.

1. Matt Adams' stack (mrwadams)

ToolWhat it isFacts checkedFit for sgit
STRIDE GPTOpen-source LLM threat modeller. Inputs: an application description, an architecture image, a draw.io diagram, a GitHub repository URL, or a local code base (stride-gpt analyze <path>, agentic: plan, explore, synthesise per subsystem). Outputs: STRIDE threat model with mitigations, attack trees, DREAD scores, Gherkin test cases, DFDs, MITRE ATT&CK and ATLAS mapping, OWASP LLM and agentic risk overlays. Formats: Markdown, JSON, SARIF, self-contained HTML; -o also writes plan, findings and run JSONgithub.com/mrwadams/stride-gpt, MIT, v0.20, about 1.1k stars. pip install stride-gpt gives the CLI; web UI from source (uv sync, Streamlit) or docker pull mrwadams/stridegpt. Anthropic is supported through LiteLLM (the README's About line still says OpenAI; it is stale). Recent PRs: threats get a stable identifier (#231), a report_threat tool that demands verifiable evidence plus a final grace round (#205), a cost estimate before an analyze run (#218)The threat-model generator for the review. Run it on the slice, in JSON, and join each threat id to a TM-R/TM-F row or to "new". The stable ids and the evidence requirement are exactly what a join needs. The code it reads is Apache-2.0 and public; never point it at a folder holding a vault key or .env
mcp-stride-gptAn MCP server that is a framework provider, not an analyser: it returns the STRIDE method, the DREAD rubric, attack-tree structure, test scaffolding and report skeletons; the client's model does the thinking. Eight tools (get_repository_analysis_guide by stage, get_stride_threat_framework, generate_threat_mitigations, calculate_threat_risk_scores, create_threat_attack_trees, generate_security_tests, generate_threat_report, validate_threat_coverage). Ships the companion stride-threat-modelling skillgithub.com/mrwadams/mcp-stride-gpt, MIT. Hosted at mcp.stridegpt.ai (claude mcp add stride-gpt https://mcp.stridegpt.ai/ --transport http), or plugin (/plugin marketplace add mrwadams/mcp-stride-gpt), or copy skills/stride-threat-modelling/ into .claude/skills/. Self-host: Python 3.12 standard library only, port 8787, no auth, keep on loopbackUse the skill copy, not the hosted endpoint. The hosted server receives the application description; the skill copy keeps everything in-session. It lets this agent do the STRIDE pass with the same rubric STRIDE GPT uses, so the two outputs are comparable
TM-BenchA benchmark for LLM threat modelling, aimed at models that run on consumer hardware. Four dimensions: STRIDE coverage and accuracy (30 %), threat completeness (30 %), technical validity (30 %), judged by an LLM (Claude Sonnet 4.6 in v2), and JSON structure compliance (10 %), scored programmatically. Three complexity tiers of application description with synthetic ground-truth modelstmbench.com (home, methodology). No public repository or dataset found; maintainer not named on the site, the support link is mrwadams. v1 used Claude 3.7 Sonnet as judge, so v1 and v2 scores are not comparableBorrow the rubric, not the harness. Our hand-written register (32 TM-R rows, 31 TM-F rows, each with a test) is a real ground truth. Scoring STRIDE GPT's output of the slice against it on TM-Bench's four dimensions is the measurable part of the case study, and a result worth sending to Matt
threat-led-triageA Claude Code / Codex skill that ranks existing findings by what an attacker can reach and chain in this code base, not by CVSS. Inputs: findings (SARIF, SCA, CVE list, pentest, or free text), the checkout, and optionally a STRIDE GPT model of the same repo (supplies the trust boundaries). Output: ranked list with per-finding reachability, code path, boundary crossed, chains, and the severity adjustment with its reason; plus an explicit "could not determine" list. It finds nothing newgithub.com/mrwadams/threat-led-triage, MIT. Run: stride-gpt analyze . -o model.json -f json, then /threat-led-triage rank findings.json against model.json for this repo. Worked example on OWASP crAPI in test/The triage step. Semgrep, Bandit, pip-audit and the review skills will produce more findings than are worth a test. Ranking them by reachability across our boundaries (host, read-key holder, local, supply chain) is how the plan stays focused
"Actions Speak Louder Than Tokens: An Insider Threat Model for Frontier AI Agents"A threat model that treats the agent as the insider. Five CERT dimensions adapted (motivation → optimisation objectives; opportunity → tool access and permissions; capability → model capabilities; predisposition → alignment profile; organisational factors → harness engineering). Four autonomy levels (L1 operator, L2 collaborator, L3 supervisor, L4 auditor). Six threat categories (credential compromise, supply-chain sabotage, data exfiltration, infrastructure sabotage, deception and evasion, containment and third-party impact). 27 STRIDE threats, each placed in a frequency × complexity quadrant (diffuse drift 10, opportunistic 8, targeted 9; the high-frequency high-complexity quadrant is empty). Detection with existing tooling: SIEM, UEBA, DLP, network, endpoint, deception (honey tokens, canary files). Monitor the shape of reasoning, not its contentai-insider-threat.matt-adams.co.uk, source github.com/mrwadams/ai-insider-threat, CC BY 4.0, v1.0 dated April 2026 with sources into August 2026. Generated with STRIDE GPT. Search snippets still say 23 threats and five categories; the page lists 27 and sixAdopt as an overlay. Several of its threats are sgit rows already, seen from the other side (table below). Adding actor A9, the agent holding the key to §3 of the threat model, and a column mapping its 27 threats to our controls, is a small, concrete piece of work with a published method behind it

Thirteen of 27 land on an existing row or mechanism after one reading. The rest (container escape, /proc reads, ptrace, cloud resource churn, flooding internal services, account creation) are host-and-harness threats that sgit cannot see; they belong in the deployment's model, which is where the paper puts them.

2. The classical tools, and why they are not first

ToolWhat it isFit
OWASP pytmThreat model as a Python file: elements, boundaries, dataflows; threat rules are Python conditions evaluated with eval (the README warns about the threat file's permissions); outputs a dot DFD, a PlantUML sequence diagram, a Markdown report. OWASP Production projectThe right shape for a repository that already keeps everything as typed data, and the model file would sit naturally beside review/intent/. Not first: its threat library is web-app shaped; our value is in the register we already have. Worth a model file once the DFD is drawn, so the DFD is data and diffs
ThreagileDeclarative YAML architecture model with automated risk rules; CLI, Docker, REST; produces risk report and diagramsSame comment; YAML rather than Python. Its risk rules are infrastructure-shaped (containers, networks); few apply to a CLI and a storage API
OWASP Threat DragonDFD editor (web or desktop) with rule-assisted threat generationA drawing tool. The house method keeps models as graph data, not drawings; use only if someone wants a picture for a talk
Microsoft TMT, IriusRisk, ThreatModelerDesktop or commercialNot for an open, agent-driven, data-first repository

3. The house method, and where each tool plugs in

From threat-modeling.sgit.ai/practice/: bottom-up and fractal (file → method → class → module → path → endpoint → attack surface); one .security.json per source file in a parallel tree with attack_surface, vulnerabilities (id, severity, attack vector, impact, status, mitigation, risk_decision with owner and rationale), secrets_exposure, dependencies with trust_boundary_crossings, redundant_code; STRIDE tables that keep NOT MITIGATED rows; two modes never averaged; the method is always published, findings only once closed or harmless by design.

House artefactProduced byNote
.security.json per file (the slice only)this agent, from the Trail of Bits dossier plus the review findings; every claim with a linethe dossier's "assumption, nothing found" rows become attack_surface and trust_boundary_crossings entries
STRIDE table for the sliceSTRIDE GPT JSON (machine) and the stride-threat-modelling skill (this agent), reconciledtwo independent passes; disagreements are published as such
Join: STRIDE threat ↔ TM-R/TM-F row ↔ testthis agent; a JSON table under review/this is the TM-Bench "completeness" measurement, with our register as ground truth
Ranked findingsthreat-led-triage over Semgrep, Bandit, pip-audit and skill output, with the STRIDE GPT modelexplicit "could not determine" kept
Actor A9 and the insider overlaythe 27-threat table above, confirmedan addition to §3 and §6 of the threat model, with Known_Gaps tests where a gap is proven
