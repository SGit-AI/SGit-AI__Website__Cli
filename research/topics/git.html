sgit and Git

The question. sgit was introduced as "git for encrypted vaults", and its guide for Git users opens with "if you know git, you know most of sgit". By 0.26.0 that undersells it: the interesting parts are the ones Git does not have. What are they, exactly, which of Git's strengths can sgit match on the client, and which does zero knowledge rule out?

The answer, row by row: sgit and Git.

sgit is a standard, not a server: everything in a vault is one hash away

People read "encrypted git" and picture a product with a server in the middle. There is a server, and it is the least interesting part. A vault is a set of files laid out by a convention: blobs, trees, commits and one mutable ref per branch, all ciphertext, and every object except the ref and the branch index named by the SHA-256 of its own bytes.

2026-10-28 · gitreview

Review: "What sgit does that Git does not", checked against the code

The sgit CLI team's review of the newsroom's article "What sgit does that Git does not" (No. 308, 27 October 2026), claim by claim against the CLI at 640069a. The article is accurate on the whole. One headline number is unsourced and one signing line is wrong. Two claims are too strong in sgit's favour: signatures prove a key holder, not a clone (TM-R01), and indexes are checked under the vault's signature policy (TM-R42). It also undersells sgit, missing partial commits with sgit write, one file with no clone on normal vaults, and seven things Git has no equivalent for. Almost everything on Git's lead can be built client-side, with how and at what size. Six things zero knowledge rules out are listed, each with its substitute.
